## B5 · 데이터베이스 — 도메인과 CRUD

**짝** — F6 표. **F6 시작 조건이 B5 완료입니다**

**시작 전 합의** — 프론트 `backend-sync.md`의 "F6 시작 전 합의할 것" 9개. **F5(=B4 배포 후)를 진행하는 동안 같이 정합니다.** 그중 제일 큰 것은 **행이 페이지인가** — `Row`와 `Page`의 관계입니다

**목표** — 표가 필요로 하는 만큼의 도메인을 세웁니다. 뷰는 안 만듭니다.

**만드는 것**

- `Database` / `Property` / `Row` 스키마와 CRUD
- 속성 7종 — 텍스트 · 숫자 · 선택 · 다중 선택 · 날짜 · 체크박스 · URL
- 속성 순서와 행 순서(`position`) — `lib/position.ts`를 그대로 씁니다

**주요 작업**

- 행의 값은 `Jsonb` 한 컬럼(`values`)에 속성 id를 키로. 속성이 추가돼도 마이그레이션이 없습니다
- 속성 타입별 값 모양을 `contract/database.ts`에 zod로. 서버가 값을 **해석하는** 유일한 도메인입니다
- 속성 삭제 시 행의 값은 남겨둡니다 (되돌릴 수 있게)
- 선택·다중 선택의 옵션 목록은 속성이 갖습니다. 별도 테이블을 만들지 않습니다

**완료 조건**

- F6이 표를 그릴 수 있다 — 행 추가·수정·삭제와 속성 추가·수정·삭제
- 잘못된 타입의 값은 `400 validation`
- 속성을 지웠다 되살리면 값이 돌아온다

## B6 · 데이터베이스 — 쿼리

**짝** — F7 보드

**목표** — 표와 보드가 같은 데이터를 다르게 보는 것뿐이게 만듭니다. **서버에는 뷰 개념이 없습니다.**

**만드는 것**

- `POST /databases/:id/rows/query` — 필터 · 정렬 · 커서 페이지네이션

**주요 작업**

- 필터를 SQL로 옮기는 변환기. **문자열을 이어 붙이지 않습니다.** 연산자를 허용 목록으로 두고 값은 파라미터로
- 연산자는 속성 타입별로 다릅니다. 타입에 없는 연산자는 `400`
- 자주 거는 속성에 표현식 인덱스
- 5000행 커서 페이지네이션. `OFFSET`을 쓰지 않습니다
- 보드의 그룹핑은 서버가 모릅니다. 선택 속성으로 필터를 걸어 여러 번 부르거나, 받아서 프론트가 나눕니다

**완료 조건**

- 5000행 + 조건 5개에서 p95 300ms
- 표와 보드가 **같은 엔드포인트**를 씁니다
- 필터 값으로 SQL을 주입할 수 없다 (테스트로 고정)

## B7 · 검색과 휴지통

**짝** — F8 검색과 정리

**목표** — 페이지가 많아져도 찾을 수 있고, 지운 걸 되돌릴 수 있게 합니다.

**만드는 것**

- `GET /search?q=&scope=&limit=` — 제목 우선, `scope=content`로 본문까지
- `GET /pages/trash` · `POST /pages/:id/restore` · `DELETE /pages/:id/purge`
- 30일 지난 휴지통 자동 정리

**주요 작업**

- Postgres 전문 검색(`tsvector`) + 생성 컬럼 + GIN 인덱스. **검색 엔진을 따로 띄우지 않습니다**
- 한국어는 기본 파서로 부족합니다. 제목은 `pg_trgm` 부분일치를 같이 씁니다
- 본문 검색은 `content`의 텍스트만 뽑아 별도 컬럼에 저장합니다. **쿼리 시점에 Jsonb를 파싱하지 않습니다** — 서버가 블록을 열어보지 않는다는 규칙과 충돌하지 않게, 추출은 저장 시점의 한 곳에서만
- 하이라이트 위치를 응답에 담습니다 (`ts_headline`)
- 복구는 뿌리의 `deletedAt`만 지웁니다. 부모가 지워져 있으면 최상위로 올립니다
- 영구 삭제는 자손까지 실제 `DELETE`

**완료 조건**

- 두 글자 검색이 1000페이지에서 p95 200ms
- 복구하면 원래 부모 아래로 돌아간다
- 부모가 없어진 페이지를 복구해도 트리에서 안 사라진다

## B8 · 파일 업로드

**짝** — F9 이미지와 파일

**목표** — 이미지와 첨부를 서버가 아니라 저장소가 받게 합니다.

**만드는 것**

- `POST /uploads` → presigned URL + `UploadTicket`
- `POST /uploads/:id/complete`
- 파일 조회 URL 발급 (만료 있는 서명 URL)

**주요 작업**

- 로컬은 MinIO, 배포는 S3 호환. **파일 바이트가 이 서버를 통과하지 않게 합니다**
- `FileAsset` 테이블 — 소유 워크스페이스, 크기, MIME, 상태(`pending`/`ready`)
- MIME과 크기를 presign 시점에 제한. 확장자를 믿지 않습니다
- `complete`가 안 온 `pending`을 주기적으로 정리
- 조회 URL은 워크스페이스 권한을 확인한 뒤 발급. **공개 버킷을 쓰지 않습니다**

**완료 조건**

- 10MB 이미지 업로드 중에도 API 지연이 안 늘어난다
- 남의 워크스페이스 파일 URL을 못 받는다
- `complete` 없이 끊긴 업로드가 하루 뒤 사라진다

## B9 · 실시간 협업 서버

**짝** — F10 실시간 협업

**시작 전 필요** — B4(권한)

**목표** — 프론트 `useEditorDoc` 안쪽에 Yjs가 들어갈 자리를 서버 쪽에서 받쳐 줍니다.

**만드는 것**

- `WS /collab?room=page:{id}` — 인증된 Yjs 동기화
- 문서 스냅샷 보관
- 접속자 목록(presence) 중계

**주요 작업**

- 방 이름은 `page:{id}`. 접속 시 **워크스페이스 권한을 확인**하고, `viewer`는 읽기만
- 업데이트를 메모리에서 병합하고 **주기적으로(예: 5초 유휴 또는 30초마다) `Page.content`에 스냅샷을 씁니다**
- **저장 경로를 하나로 합칩니다.** B3의 `PATCH` 저장과 스냅샷 저장이 서로 덮어쓰면 글자가 사라집니다. 협업이 켜진 페이지는 `PATCH`로 `content`를 못 바꾸게 막는 쪽이 안전합니다
- 기존 `content`(BlockNote JSON) → Y.Doc 변환 경로. 되돌릴 수 없으므로 변환 전 스냅샷을 남깁니다
- 마지막 접속자가 나가면 방을 정리하되, 스냅샷을 먼저 씁니다
- 프로세스가 여러 개가 되면 방을 프로세스에 고정하거나 Redis 중계가 필요합니다. **한 프로세스로 시작하고, 필요해질 때 넣습니다**

**완료 조건**

- 두 탭에서 같은 문단을 동시에 쳐도 글자가 안 사라진다
- 서버를 재시작해도 마지막 스냅샷까지 남는다
- `viewer`는 연결은 되지만 변경을 밀어넣을 수 없다
- 저장 경로가 하나뿐이다
- 100개 방 동시 접속에서 메모리가 선형으로만 는다
