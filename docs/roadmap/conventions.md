## 모든 스프린트의 완료 조건

각 스프린트 문서의 완료 조건에 **더해서** 아래를 매번 확인합니다.

### 코드

- [ ] `npm run typecheck` 통과
- [ ] `npm run build` 통과
- [ ] `npm run test:run` 통과
- [ ] 새 엔드포인트마다 통합 테스트 1개

### 계약

- [ ] 응답이 `src/contract/` 스키마를 통과한다
- [ ] 계약을 고쳤으면 프론트 `types/api.ts`도 **같은 날** 고쳤다
- [ ] 새 오류가 [계약된 코드](api-contract.md#에러-응답) 안에 있다

### 경계

```bash
grep -rn "prisma\." src/modules/*/*.routes.ts
```
```bash
grep -rnE "\b(request|reply)\b" src/modules/*/*.service.ts
```
```bash
grep -rn "process.env" src --include=*.ts | grep -v "src/config.ts"
```

세 개 다 결과가 없어야 합니다.

### 데이터

- [ ] 마이그레이션이 **되돌릴 수 있거나**, 못 되돌린다면 그렇다고 적혀 있다
- [ ] 새 쿼리에 `workspaceId` 조건이 있다 (B4부터)
- [ ] 새 조회 경로에 `deletedAt` 처리가 있다

### 로그

- [ ] 본문·토큰·비밀번호가 로그에 안 남는다
- [ ] 5xx가 `requestId`와 함께 남는다

## API 변경 규칙

계약이 어긋나면 **화면이 조용히 잘못된 값을 그립니다.** 런타임 검증이 붙는 F9 전까지는 아무도 모릅니다.

**1. 계약 변경은 한 번에 양쪽을 고칩니다.**
`src/contract/`와 프론트 `src/types/api.ts`를 같은 날 고치고, 커밋 메시지에 상대 저장소를 적습니다.

**2. 필드를 지우거나 이름을 바꾸는 건 배포가 두 단계입니다.**
새 필드를 추가하고 → 프론트가 옮겨간 뒤 → 옛 필드를 지웁니다. 한 번에 하면 배포 순서에 따라 화면이 깨집니다.

**3. 선택 필드를 필수로 바꾸지 않습니다.**
기존 프론트가 안 보내면 전부 `400`이 됩니다. 새 필수 필드는 새 엔드포인트로 갑니다.

**4. 오류 코드는 [계약 표](api-contract.md#에러-응답)에서만 고릅니다.**
새 코드가 필요하면 표를 먼저 고칩니다. 프론트는 모르는 코드를 `unknown`으로 뭉갭니다.

## 마이그레이션 규칙

- 마이그레이션 파일을 **손으로 고치지 않습니다.** 이미 적용된 걸 고치면 다른 환경과 어긋납니다
- 컬럼 삭제와 코드 배포를 같은 배포에 넣지 않습니다
- 데이터를 옮기는 마이그레이션은 롤백 방법을 커밋 메시지에 적습니다
- `prisma migrate reset`은 로컬에서만. 스크립트에 프로덕션 접속 정보가 닿지 않게 합니다

## 문서 관리 규칙

프론트와 같은 규칙을 씁니다.

**1. 완료된 스프린트 문서는 갱신하지 않고 지웁니다.** 남길 게 있으면 규칙으로 바꿔 `architecture.md`나 이 문서로 옮깁니다.

**2. "지금 상태"는 `ROADMAP.md` 한 곳에만 적습니다.**

**3. 코드나 git이 이미 말해주는 것은 적지 않습니다.** 스키마 필드는 `prisma/schema.prisma`, 타입은 `src/contract/`가 유일한 출처입니다.

**4. 먼 계획은 자세히 쓰지 않습니다.** B5 이후는 개요만 두고 시작 직전에 풉니다.

## 커밋 규칙

프론트와 같습니다.

```
feat:      기능 추가
fix:       버그 수정
refactor:  동작 변화 없는 정리
chore:     설정·의존성
test:      테스트
docs:      문서
```

한 커밋은 하나만 합니다. 마이그레이션은 그걸 쓰는 코드와 같은 커밋에 둡니다.

## 리스크

| 리스크 | 생기면 | 대비 |
|---|---|---|
| **F9가 mock 4주치를 한 번에 걷어내려 함** | F9가 1주로 안 끝남 | 아래 [전환은 도메인 단위로](#전환은-도메인-단위로) |
| 계약이 늦게 확정됨 | 양쪽을 다 고쳐야 함 | B1을 F4와 겹쳐서 진행. B1 완료 조건에 "필드 100% 대조" |
| `position` 정밀도 고갈 | F5 드래그 이동에서 순서가 뒤집힘 | B1에서 재배치 규칙을 정하고 **50회 반복 테스트**로 고정 |
| B3 저장과 B8 스냅샷이 서로 덮어씀 | 글자가 사라짐 | B8에서 저장 경로를 하나로 합침. 협업 중 `PATCH content` 차단 |
| 워크스페이스 스코프 누락 | 남의 문서가 보임 | repo 함수가 `workspaceId`를 **필수 인자**로 받게. 인증 필요 경로 목록을 테스트로 고정 |
| 본문 크기가 예상보다 큼 | 저장이 느려지고 타이핑이 밀림 | B3 부하 테스트를 100KB·1MB 두 가지로 |
| 검색을 위해 서버가 블록을 열어봄 | B8에서 `content`가 Yjs로 바뀔 때 깨짐 | 텍스트 추출은 **저장 시점 한 곳**에서만. 쿼리에서 Jsonb를 파싱하지 않음 |

### 전환은 도메인 단위로

프론트 F9의 목표는 "mock을 걷어내고 실서버에 붙이기"입니다. 그런데 F9 시점에는 프론트가 F5~F8에서 검색·파일·데이터베이스 mock까지 다 만들어 둔 상태입니다. 그걸 전부 받으려면 백엔드는 B1~B7을 F9 앞에 끝내야 합니다. **1인 개발로는 안 맞습니다.**

권장 — `api/client.ts`의 mock/실서버 스위치를 **도메인별로** 둡니다.

```
VITE_API_PAGES=server
VITE_API_SEARCH=mock
VITE_API_FILES=mock
```

이러면 F9는 "pages + auth를 실서버로"만 하면 되고, 나머지는 백엔드가 따라잡는 대로 한 줄씩 바꿉니다. 프론트가 경계 규칙(`knocspace-web`의 `docs/roadmap/architecture.md`)을 지켰다면 `api/` 안에서만 바뀌므로 화면 코드는 여전히 0줄입니다.

**B4가 끝나기 전에 프론트와 이걸 합의합니다.**

## 스프린트 시작·종료 절차

**시작할 때**

1. 해당 스프린트 문서를 읽습니다
2. [API 계약](api-contract.md)에서 이번에 건드릴 엔드포인트를 확인합니다
3. 계약에 미결정이 남아 있으면 **코드보다 먼저** 결정합니다

**끝낼 때**

1. 스프린트 문서의 완료 조건 체크
2. 이 문서의 공통 완료 조건 체크
3. 계약이 바뀌었으면 프론트에 반영됐는지 확인
4. 다음 스프린트 문서를 상세하게 풀어 씁니다 (B5부터)
