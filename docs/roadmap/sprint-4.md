## 목표

여러 사람이 로그인해서 각자의 워크스페이스를 씁니다. 그리고 **남의 문서가 절대 안 보이게** 합니다.

B1~B3의 모든 요청은 시드 사용자 `local-user`로 돌았습니다. 이번 주에 그걸 걷어냅니다.

## 만드는 것

- 로그인 · 토큰 갱신 · 로그아웃
- 워크스페이스 멤버십과 권한 2단계
- 모든 페이지 쿼리의 워크스페이스 스코프
- rate limit, 보안 헤더
- `local-user` 승격 마이그레이션

---

## 할 일

### 1. 사용자와 토큰

- [ ] `User`에 `passwordHash` 추가. **argon2id** (bcrypt는 새로 안 씁니다)
- [ ] `POST /auth/login` → `{ accessToken, user }` + refresh 토큰 쿠키
  - access 15분, refresh 30일
  - refresh는 `httpOnly` `secure` `sameSite=lax` 쿠키. **응답 본문에 담지 않습니다**
- [ ] `POST /auth/refresh` — 쿠키로 갱신. **쓸 때마다 새 토큰으로 회전**하고 이전 것을 폐기
  - 폐기된 토큰이 다시 오면 그 사용자의 전체 refresh를 무효화합니다 (탈취 신호)
- [ ] `POST /auth/logout` → `204`
- [ ] `GET /auth/me` → `User`
- [ ] `User.color`는 가입 시 고정 팔레트에서 배정. **B9 커서 색으로 그대로 씁니다**

계정 생성 화면은 이번 범위가 아닙니다. `db:seed`로 계정을 만듭니다.

### 2. 인증 플러그인

- [ ] `plugins/auth.ts` — `Bearer` 검증 → `request.user`
- [ ] **기본이 "인증 필요"입니다.** 공개 경로(`/health` `/ready` `/auth/login` `/auth/refresh`)만 예외로 표시합니다
  - 반대로 하면 새 엔드포인트를 만들 때마다 보호를 깜빡할 수 있습니다
- [ ] 토큰 없음·만료 → `401 unauthorized`

### 3. 워크스페이스와 권한

- [ ] `Membership.role` — `owner` / `editor` / `viewer`
- [ ] `GET /workspaces/me` — 내가 속한 워크스페이스 목록
- [ ] **모든 페이지 쿼리에 `workspaceId` 조건이 붙습니다.** repo 레이어에서 강제합니다
  - service가 깜빡해도 새어 나가지 않게, `pages.repo.ts`의 모든 함수가 `workspaceId`를 **필수 인자**로 받게 만듭니다
- [ ] 권한 확인은 service에서 한 곳(`assertCanEdit` / `assertCanView`)
- [ ] `viewer`가 수정·삭제를 시도하면 `403 forbidden`
- [ ] 다른 워크스페이스의 페이지는 `404 not_found` — `403`이 아닙니다. id의 존재가 새어 나갑니다
- [ ] **`POST /pages`의 멱등 조회에도 `workspaceId` 조건을 붙입니다.** id는 클라이언트가 만들어 보내는 전역 PK라, 조건이 없으면 남의 워크스페이스 id를 찍어 보낸 요청이 그 페이지를 통째로 받습니다. 다른 워크스페이스의 id면 `404`
  - [ ] id가 UUID인 것은 이 조건을 대신하지 않습니다. 찍어 맞히기 어려워졌을 뿐이고, 공유 링크로 새어 나간 id 하나면 같은 일이 벌어집니다
  - [ ] 이 케이스를 테스트로 고정합니다 — 다른 워크스페이스 페이지 id로 `POST` 하면 `404`이고 그 페이지는 안 변한다

#### 워크스페이스를 만드는 API는 B4에 없습니다

`GET /workspaces/me` 하나뿐입니다. 생성·이름 변경·삭제는 없고, 워크스페이스는 계정과 같이 `db:seed`로 만듭니다.

Notion에서 워크스페이스가 생기는 시점이 두 군데인데, **둘 다 이 저장소의 첫 목표 밖**이기 때문입니다.

| Notion | 이쪽 |
|---|---|
| 가입 온보딩에서 첫 워크스페이스를 만들거나, 초대·이메일 도메인으로 기존 워크스페이스에 합류 | 회원가입 화면이 [계획 밖](scope.md#빼는-것)입니다 |
| 그 뒤로는 좌상단 스위처에서 아무 때나 추가 생성 (개수 제한 없음) | 워크스페이스를 여러 개 쓸 이유가 아직 없습니다. 한 계정이 여러 워크스페이스에 속할 수 있게 **모양만** 갖추고, 만드는 경로는 안 엽니다 |
| 삭제는 Settings → General → Danger zone, **워크스페이스 owner만** | `Membership.role`의 `owner`가 그 자리입니다 |

**미루는 게 싼 이유** — Notion은 계정과 워크스페이스가 별개고 멤버십으로 N:M입니다. B1이 만든 `Workspace`와 이번에 만드는 `Membership`이 이미 그 모양이라, 나중에 `POST /workspaces`가 생겨도 **마이그레이션 없이 라우트 하나만 붙습니다.** 되돌리기 싼 결정이라 지금 정하지 않습니다.

**지금 정해 두는 것 하나** — `Membership.role`에 `owner`를 남깁니다. 지금은 `editor`와 권한이 같아서 지금 지워도 되지만, owner는 "워크스페이스를 지울 수 있는 사람"이라 값이 찬 뒤에 끼워넣는 쪽이 비쌉니다.

### 4. 데이터 이관

- [ ] 마이그레이션 — 기존 `local-user`를 실제 계정으로 승격하고, 기존 페이지의 `createdBy`/`updatedBy`를 유지
- [ ] 시드에서 `local-user` 특례를 제거
- [ ] B1~B3에서 쓰던 "인증 없으면 시드 사용자" 분기를 **전부 지웁니다.** 하나라도 남으면 인증 우회로가 됩니다
- [ ] `src/local-defaults.ts` 파일 자체를 지웁니다. 파일이 사라지면 임시 분기가 남았는지 `grep`으로 확인할 필요가 없습니다

### 5. 방어

- [ ] `@fastify/helmet` — 보안 헤더
- [ ] `@fastify/rate-limit` — 로그인은 IP당 분당 10회, 나머지는 사용자당 분당 300회 → `429 rate_limited`
- [ ] CORS에 `credentials: true`, 허용 출처는 `config`에서
- [ ] 로그인 실패 응답은 **"이메일이 없음"과 "비밀번호 틀림"을 구분하지 않습니다**
- [ ] 로그에 토큰·비밀번호가 안 남는지 확인

### 6. 테스트

- [ ] 토큰 없이 페이지 요청 → `401`
- [ ] 남의 워크스페이스 페이지 조회 → `404`
- [ ] `viewer`가 `PATCH` → `403`, 데이터 안 바뀜
- [ ] refresh 회전 — 옛 토큰 재사용 시 전체 무효화
- [ ] 만료된 access 토큰 → `401`
- [ ] **인증이 필요 없는 경로 목록이 예상과 정확히 같은지** 확인하는 테스트 하나

마지막 것을 자동 테스트로 둡니다. 나중에 엔드포인트가 늘어나도 보호가 빠지지 않습니다.

### 7. 마무리

- [ ] README 갱신 — 계정 만드는 법
- [ ] `/docs`에 `Bearer` 인증이 표시되고, 공개 경로가 구분돼 보입니다

## 완료 조건

- [ ] 로그인 → 자기 워크스페이스 페이지만 조회됨 → 새로고침해도 유지
- [ ] 남의 워크스페이스 페이지 id로 조회하면 `404`
- [ ] `viewer` 토큰으로는 `PATCH`가 `403`
- [ ] 인증 우회 경로 0개 — 시드 사용자 분기가 코드에 안 남아 있다
- [ ] `src/local-defaults.ts`가 저장소에 없다
- [ ] `pages.repo.ts`의 모든 함수가 `workspaceId`를 필수 인자로 받는다 (타입으로 강제)

[공통 완료 조건](conventions.md)도 함께 확인합니다.

## 끝나면 할 수 있는 것

여러 사람이 로그인해서 각자의 워크스페이스에서 문서를 씁니다. 남의 문서는 안 보입니다.

공유는 되지만 동시에 고치면 마지막에 저장한 사람이 이깁니다. 그건 협업 스프린트입니다.
